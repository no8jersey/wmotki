# Сайт: восемь независимых окон по твоей схеме

На странице нет видимых текстов, заголовков, счетчиков, точек или стрелок. Названия категорий используются только в настройках и для программ чтения с экрана. Тонкие рамки обозначают окна; подложка у всех прозрачная, фон общий.

Расположение сохраняется и на телефоне:

| Ряд | Слева | По центру | Справа |
| --- | --- | --- | --- |
| 1 | — | hat | — |
| 2 | shirt | longsleeve | jacket |
| 3 | pants | belt | bag |
| 4 | — | shoes | — |

В папках лежат демонстрационные SVG одежды. Замени их своими изображениями. Дополнительная папка images/vases уже содержит три демо-вазы, но не подключена к окну — ниже показано, как ее подключить.

## Как листать

- Нажатие на правую половину окна — следующая картинка.
- Нажатие на левую половину — предыдущая.
- Горизонтальный свайп — переключение.
- Tab выбирает окно или невидимую кнопку, ← и → листают выбранное окно. При навигации клавиатурой появляется контур фокуса.
- В каждом окне свой список и свой текущий кадр. Автопрокрутки нет.
- Если в категории одна картинка, она просто отображается. Если нет ни одной, остается пустое прозрачное окно.

## 1. Проверка на компьютере

Распакуй архив и дважды нажми index.html. В архиве уже есть gallery-data.js со списком демонстрационных изображений, поэтому пример работает без сервера.

После изменения состава папок локально список сам не обновляется: либо загрузи изменения на GitHub (список пересоберется автоматически), либо, если у тебя установлен Python, запусти в папке проекта `python build.py` и заново открой index.html. Устанавливать Python на свой компьютер для работы через GitHub не нужно.

## 2. Обновление сайта на GitHub — один раз

1. Открой свой репозиторий → Code → Add file → Upload files.
2. Перетащи содержимое распакованной папки slider-site в репозиторий. Загружай содержимое, а не ZIP и не дополнительную внешнюю папку slider-site.
3. Согласись заменить файлы предыдущего варианта этого сайта: index.html, styles.css, script.js и README.md. Остальные свои файлы удалять не нужно.
4. Обязательно загрузи новые theme.css, site.config.json, gallery-data.js, build.py, images, backgrounds и папку .github с вложенными workflows/pages.yml.
5. Нажми Commit changes и сохрани в основную ветку. Дальше инструкция работает и с main, и с master: сценарий определяет основную ветку автоматически.
6. В репозитории открой Settings → Pages → Build and deployment → Source → GitHub Actions. Старый вариант Deploy from a branch для этой версии не подходит: он не пересобирает категории.
7. Открой вкладку Actions → Publish gallery → Run workflow. Выбери основную ветку и нажми зеленую кнопку Run workflow. Ручной запуск нужен после первоначальной настройки; следующие сохранения запустят публикацию автоматически.
8. Дождись зеленой отметки у задачи. Ссылка на сайт находится в Settings → Pages / Visit site. Адрес существующего сайта сохраняется.

Если автоматический запуск при первой загрузке завершился ошибкой до включения Pages, просто выполни шаги 6–7.

Если GitHub предлагает Enable workflows, включи их. Если задача ожидает разрешения на публикацию, смотри ее сообщение во вкладке Actions; в репозитории должны быть разрешены GitHub Actions и GitHub Pages.

На GitHub Free нужен публичный репозиторий. Не меняй приватность репозитория с личными материалами ради сайта: для него можно создать отдельный публичный репозиторий.

### Если папка .github не загрузилась

Открой локально .github/workflows/pages.yml в Блокноте. На GitHub нажми Add file → Create new file и в имени укажи `.github/workflows/pages.yml`. Скопируй туда весь текст файла, затем Commit changes. Тот же текст приведен в конце этой инструкции. Название должно оканчиваться именно на .yml, не .yml.txt.

## 3. Как добавлять картинки по категориям

| Окно | Папка |
| --- | --- |
| Головные уборы, сверху по центру | images/hat |
| Футболки, второй ряд слева | images/shirt |
| Лонгсливы, второй ряд по центру | images/longsleeve |
| Куртки, второй ряд справа | images/jacket |
| Брюки, третий ряд слева | images/pants |
| Ремни, третий ряд по центру | images/belt |
| Сумки, третий ряд справа | images/bag |
| Обувь, снизу по центру | images/shoes |

Пример: добавляем пять головных уборов.

1. В репозитории открой images → hat.
2. Нажми Add file → Upload files.
3. Перетащи свои пять изображений прямо в эту папку.
4. Нажми Commit changes.
5. Дождись зеленой отметки публикации в Actions и обнови сайт.

Все пять файлов попадут только в верхнее окно. Писать имена файлов в JavaScript не надо. Скрипт сборки читает файлы непосредственно внутри каждой назначенной папки, а не из вложенных в нее подпапок.

Демонстрационные demo-01.svg, demo-02.svg и demo-03.svg нужно удалить из категории, если хочешь видеть только свои картинки. Открой файл на GitHub → меню ... → Delete file → Commit changes. Не удаляй .gitkeep: он сохраняет папку, когда в ней нет картинок.

Порядок определяется именами файлов с учетом чисел. Для понятного порядка назови свои файлы 01.png, 02.png, 03.png и так далее. Поддерживаются PNG, WebP, SVG, JPG/JPEG, GIF, AVIF; настоящая прозрачность нужна именно в исходном файле, JPEG ее не поддерживает.

Удаление файла из папки тоже автоматически удаляет его из слайдера после публикации.

## 4. Как заменить категорию окна, например на вазы

Папка images/vases уже есть в архиве, и в ней три демонстрационные вазы. Загрузи туда свои пять картинок и удали демо.

Открой site.config.json на GitHub и нажми карандаш. Найди объект нужного окна, например верхнего:

```json
{
  "slot": "hat",
  "category": "hat",
  "label": "Головные уборы"
}
```

Замени его на:

```json
{
  "slot": "hat",
  "category": "vases",
  "label": "Вазы"
}
```

- slot — место окна на схеме. Оставь hat, чтобы окно оставалось сверху по центру.
- category — название папки внутри images. Теперь это vases.
- label — название для программ чтения с экрана. На странице его не видно.

Сохрани Commit changes. После публикации в верхнем окне будут только файлы из images/vases. Остальные семь окон не изменятся.

Создать новую категорию тоже можно: Add file → Create new file → имя images/my-category/.gitkeep → Commit changes. Затем открой созданную папку и загрузи картинки. В site.config.json назначь одному из существующих окон category: my-category. В имени папки используй латиницу, цифры, дефис или нижнее подчеркивание.

Сама новая папка не создает девятое окно: схема фиксирована на восемь. Новую категорию нужно один раз привязать к одному из этих окон. После этого добавление файлов в нее полностью автоматическое.

## 5. Как поменять фон

Открой theme.css → карандаш. Все настройки находятся в начале файла.

### Однотонный фон

Замени значение:

```css
--background-color: #ffffff;
```

Например, бежевый: #eee7dc, черный: #111111. Для однотонного фона оставь:

```css
--background-image: none;
```

### Своя фоновая картинка

1. Открой backgrounds на GitHub и загрузи background.jpg (можно и PNG/WebP).
2. В theme.css замени строку --background-image: none; на:

```css
--background-image: url('./backgrounds/background.jpg');
```

Если файл называется иначе, укажи его точное имя и расширение.

Фон заполняет экран с сохранением пропорций; края могут обрезаться из-за cover. Чтобы показать картинку целиком, установи --background-size: contain; — по краям тогда может быть виден основной цвет.

### Градиент

```css
--background-image: linear-gradient(135deg, #fff1df, #dce9ff);
```

### Совсем убрать рамки окон

```css
--window-border: 0;
```

Фон всегда общий для всей страницы. В коде не нужно задавать отдельный фон каждому окну. Серые прямоугольники с референса использованы как схема расположения, а не как фон карточек.

После любой правки нажми Commit changes, дождись публикации и обнови сайт. Если видна старая версия — Ctrl+F5.

## Что делает автоматизация

GitHub Actions запускает build.py после сохранения изменений в основной ветке. Скрипт смотрит site.config.json, считывает картинки из папок категорий, создает gallery-data.js и публикуемую папку dist. Затем GitHub Pages публикует dist. Токены и пароли в код вставлять не нужно.

gallery-data.js в самом репозитории может содержать старые демонстрационные данные: он служит для локального примера. При каждой публикации в Actions файл генерируется заново. Автоматизация не делает дополнительных коммитов в репозиторий.

Не загружай dist вручную и не редактируй gallery-data.js для добавления изображений. Фоновая картинка хранится отдельно в backgrounds, чтобы не попадать в слайдеры.

## Если не работает

| Симптом | Проверка |
| --- | --- |
| Новые изображения не появляются | Source должен быть GitHub Actions; последний Publish gallery должен завершиться успешно; загружай в папку, указанную в category |
| Видна старая сетка | Загружены ли новые index.html, styles.css и script.js; завершилась ли публикация; Ctrl+F5 |
| Не видно окна | В категории может не быть изображений; при отключенных рамках пустое окно полностью прозрачно |
| Пустой кадр среди других | Проверь сам файл изображения, его формат и загрузку; нажми правую половину, чтобы перейти дальше |
| Сборка пишет «Нет папки» | category не совпадает с именем папки; регистр учитывается; создай папку или исправь настройку |
| Не видно Publish gallery | Проверь точный путь .github/workflows/pages.yml в основной ветке |
| Пять ваз плюс три лишние картинки | Удали демонстрационные изображения из images/vases |
| Изображение с белой/клетчатой подложкой | Подложка записана в картинке; нужен файл с настоящей прозрачностью |
| После локального добавления картинки ничего не изменилось | Автообновление работает после публикации на GitHub; локально запусти python build.py при установленном Python |

## Официальные инструкции

- https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Текст .github/workflows/pages.yml для ручного создания

```yaml
name: Publish gallery

on:
  push:
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: github-pages
  cancel-in-progress: false

jobs:
  build-and-deploy:
    if: github.ref == format('refs/heads/{0}', github.event.repository.default_branch)
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Download repository
        uses: actions/checkout@v6
      - name: Configure Pages
        uses: actions/configure-pages@v5
      - name: Scan categories and build website
        run: python3 build.py
      - name: Upload website
        uses: actions/upload-pages-artifact@v4
        with:
          path: dist
      - name: Publish website
        id: deployment
        uses: actions/deploy-pages@v4
```
